# 데이터 파이프라인

「2027년 천안시 유기·유실동물 구조(포획) 용역 과업지시서」와 선행연구 검토 결과(`review/`)를 바탕으로, 분석에 필요한 공공데이터를 자동으로 수집하고 1차 분석까지 하는 파이프라인이에요.

## 구조

```
수집(collect*.py) → 원본 보관(data/raw) → 검증·정제(process.py) → 정제 데이터(data/processed) → 1차 분석(analyze.py) → analysis/
```

| 단계 | 파일 | 하는 일 |
|---|---|---|
| 1-1 수집 | `collect.py` | 국가동물보호정보시스템 구조동물 API에서 천안시 공고를 월 단위로 수집. 이미 받은 달은 건너뛰고, 최근 2개월은 다시 받음. API 총건수와 받은 건수가 같아야 '완료' |
| 1-2 수집 | `collect_population.py` | KOSIS 천안시 연도별 주민등록인구(인구 대비 지표용) |
| 2~3 검증·정제 | `process.py` | 필수 항목·날짜 검증, 공고번호 중복 제거, 처리결과·나이·체중·지역 정제 |
| 4 분석 | `analyze.py` | 과업지시서 조항별 1차 분석, 그림·표·보고서 생성 |
| 공통 | `api.py` | API 호출, 재시도(지수 백오프), 오류 메시지 |

GitHub에서 이 API를 쓰는 공개 수집 코드는 찾지 못했어요. 그래서 데이터 수집 코드에서 흔히 쓰는 원칙을 따랐어요.
- 원본 보존
- 이어받기·멱등성(다시 돌려도 같은 결과)
- 완결성 검사
- 검증 실패 행은 사유와 함께 기록

## 실행

```bash
pip install pandas matplotlib requests
export DATA_GO_KR_KEY='공공데이터포털 일반 인증키(Decoding)'
export KOSIS_API_KEY='KOSIS 인증키'
python pipeline/run_all.py
```

- 인증키는 코드나 저장소에 넣지 않아요. 환경변수로만 전달해요.
- 공공데이터포털에서 「농림축산식품부 농림축산검역본부_국가동물보호정보시스템 구조동물 조회 서비스」 활용신청이 승인된 키여야 해요.
- 담당자 이름·사무실 전화번호는 개인정보라 저장하지 않아요.
- `data/raw/`(원본 JSON)는 원래 용량 때문에 저장소에 올리지 않지만, 이번 수집분은 보존하려고 함께 올렸어요(아래 현재 상태 참고). 정제 데이터 `data/processed/cheonan_rescues.csv`는 올려요.

## 현재 상태 (2026-11-28)

- **전체 수집 완료**: 2019년 1월 ~ 2026년 11월(95개월), **9,384건**. 불완전한 달 0개(`data/collection_log.json`).
  - 원천 누락 2건: 2021년 5월·2023년 2월에 API가 총건수에는 '개' 1건씩을 더 세지만 목록으로는 주지 않아요. 페이지 크기(50·1000), 축종별 조회를 바꿔도 받을 수 없어서 `collect.py`의 `KNOWN_SOURCE_GAPS`에 기록하고 보고서에도 밝혔어요.
  - 2026년 11월은 27일까지예요(수집일 전날 기준).
- **정제(`process.py`)**: 9,384건 → 형식 오류 0건, 중복 0건 → 9,384건(`data/processed/`).
- **1차 분석(`analyze.py`)**: 오류·경고 없이 실행 완료. 결과는 `analysis/REPORT.md`, 그림 7개(`analysis/figures/`), 표 11개(`analysis/tables/`).
- **원본 보관**: 이 클라우드 작업 공간에서는 공공데이터포털 연결이 자주 끊겨 다시 받기 어려워서, 원본 `data/raw/`(약 11MB)도 받은 그대로 저장소에 함께 올렸어요.
